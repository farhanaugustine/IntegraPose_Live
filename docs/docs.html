01 · Start here

Getting started

IntegraPose Live is distributed as an Android Studio source project for developers, advanced users, and technical research collaborators. The supported installation path is a debug build deployed directly through Android Debug Bridge (ADB).

Active development: features can be incomplete or change without notice. Validate the app, device, model, and sustained recording workflow before relying on it for an experiment.

Requirements

  • Android 8.0 (API 26) or newer
  • Android Studio with JDK 17
  • Android SDK Platform 35
  • Android NDK 29.0.14206865 and CMake 3.22.1
  • A compatible user-supplied ONNX file or NCNN package
  • Enough storage for models, source media, and outputs

Quick start

  1. Open Models and import a compatible model.
  2. Review task, input size, labels, output format, and detection count.
  3. Run Benchmark for NCNN on the target device.
  4. Choose Live, Image, or Offline.
  5. Configure recording, tracking, behavior, skeleton, and ROI options.
  6. Review and explicitly share the generated video and CSV files.

02 · Build

Install with Android Studio

Open the project

  1. Install Android Studio from the official Android Developers site.
  2. Choose Get from VCS to clone, or Open if already downloaded.
  3. Select the folder containing settings.gradle.kts—not only the app subfolder.
  4. Trust only a recognized source, then allow Gradle sync to finish.

Configure the toolchain

Accept prompts for the required SDK, NDK, and CMake components. If Gradle reports an incompatible Java runtime, set Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK to JDK 17.

Connect a phone

  1. Enable Developer Options by tapping the phone’s build number seven times.
  2. Enable USB debugging and connect with a USB data cable.
  3. Accept debugging authorization only after verifying the computer.
  4. Select the debug variant and app run configuration.
  5. Choose the phone and click Run.
Direct ADB installation does not require a Play Console account, release keystore, or public APK. The app remains installed after the cable is disconnected.

Command line

# Windows PowerShell
$env:JAVA_HOME = "C:\path\to\jdk-17"
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug

# macOS / Linux
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug

03 · Compatibility

Model contract

Compatibility is determined by input, output, metadata, and tensor layout—not by training framework or model-family name. Classification, segmentation, oriented boxes, heatmap-only pose outputs, and formats other than ONNX and NCNN are not supported.

RuntimeRequired filesSupported layouts
ONNX Runtime CPUOne .onnx fileRaw candidates or final detections, with optional keypoints
NCNN CPU / Vulkanmodel.ncnn.param, model.ncnn.bin, metadata.yamlRaw bbox/class candidates, with optional keypoints

Shared preprocessing

The app letterboxes with gray value 114, reads RGB channels, and scales pixels to 0.0–1.0. Models requiring BGR, mean subtraction, custom standardization, multiple image inputs, or other preprocessing are not directly compatible.

ONNX contract

  • One 4D image input; batch size 1; RGB in NCHW or NHWC.
  • FLOAT, FLOAT16, or BFLOAT16 input.
  • A positive fixed size or compatible dynamic size.
  • A 2D or 3D floating-point detection/pose tensor as first output.

NCNN package

  • The three exact filenames must be at the selected folder’s top level.
  • Input blob in0; output blob out0.
  • One square, 3-channel RGB float input and one 2D raw-candidate output.
  • Input size is a multiple of 32 between 32 and 2048.
  • Metadata declares detection or pose with end2end: false and nms: false.
model_name: Example pose model
task: pose
imgsz: [480, 480]
names:
  0: animal
kpt_shape: [7, 3]
end2end: false
nms: false

Raw output row

[center_x, center_y, width, height, class_scores...,
 keypoint_x, keypoint_y, keypoint_confidence...]

Final ONNX row

[x1, y1, x2, y2, confidence, class_id,
 keypoint_x, keypoint_y, keypoint_confidence...]

For raw predictions, the app applies confidence filtering, class-aware NMS, and the configured detection cap. Increase detection count when multiple concurrent subjects are expected; it is a cap, not a single-subject restriction.

04 · Run

Inference workflows

Live

Run camera inference with optional raw and annotated recording. Stop & save stops new inference frames, finalizes requested videos, and then builds CSV analytics. Keep the app on the active tab until saving completes.

Image

Select a still image, inspect detections or pose keypoints, benchmark the model, and share the rendered PNG or per-image CSV.

Offline

Select prerecorded video, choose outputs, optionally define ROIs, and process. Stop and save completes the active frame and preserves usable partial output.

Pose skeletons

Under Settings → Pose skeleton, provide zero-based connections such as 0-1, 1-2. Use the training dataset’s keypoint order; the app does not infer an animal-specific skeleton.

05 · Measure

Exports and analytics

  • Per-frame detection and pose CSV
  • Raw and annotated MP4
  • Class-agnostic IoU track IDs
  • Mutually exclusive behavior bouts from the highest-confidence class
  • Named rectangular ROI entry, exit, and dwell events

Regions of interest

Draw, move, resize, and rename multiple rectangular ROIs. Offline uses the first frame; Live captures the next camera frame and matches preview crop, orientation, and mirroring.

SettingDefaultMeaning
Maximum frame gap5 framesMissing frames bridged within a behavior bout
Minimum bout duration3 framesShortest summarized bout
Maximum ROI gap5 framesMissing frames bridged in one ROI visit
Minimum ROI dwell3 framesShortest summarized ROI visit
ROI entry / exit0.75 / 0.25Hysteresis thresholds reducing boundary flicker

Bout and visit frame ranges are inclusive. Shorter contacts remain in per-frame output but are omitted from event summaries.

06 · Validate

Benchmarking and performance

For NCNN, the benchmark evaluates CPU and available Vulkan configurations. When Vulkan runs, it compares predictions with CPU output. Automatic selection chooses Vulkan only when agreement passes and the eligible GPU path is faster.

Live/Image and Offline may retain separate profiles. Performance depends on model, input size, device, decoder/encoder, memory, and temperature. Benchmarking does not replace a sustained run on representative media.

A phone can throttle as it heats. Validate sustained throughput, storage reserve, battery settings, and output correctness—not only a short peak benchmark.

07 · Data handling

Privacy

  • Camera frames and selected media are processed locally.
  • Source documents are opened read-only.
  • Imported models and provider-backed videos are copied into app-owned storage.
  • The app requests no Android network permission.
  • Android cloud backup is disabled.
  • Raw live recordings capture no audio.
  • Content leaves only through explicit share/export.

08 · Know the edges

Known limitations

  • Support is limited to the documented detection and pose layouts.
  • Tracking uses basic class-agnostic IoU association; re-identification is not implemented.
  • Vulkan support and speed vary by device and model.
  • Long recordings can heat a device and reduce throughput.
  • Import validation cannot prove semantic correctness; inspect representative results.
  • Testing has focused primarily on a Samsung Galaxy S23 Ultra; other devices can differ.

09 · Recover

Troubleshooting

Phone does not appear

Unlock it, confirm the cable supports data, choose data-transfer mode, try another port, and check the debugging prompt. Windows may require a manufacturer USB driver.

Gradle sync fails

Confirm JDK 17, initial internet access, SDK Platform 35, NDK 29.0.14206865, and CMake 3.22.1.

Model import fails

For NCNN, select the folder containing the exact top-level filenames. Check UTF-8 metadata, in0/out0, square RGB input, and raw non-NMS output.

Results look wrong

Check task, label order, input size, output layout, detection count, confidence/NMS, coordinate scale, and pose keypoint order. File format alone does not establish compatibility.

Vulkan is unavailable

Use NCNN CPU and run the built-in benchmark. Vulkan is optional; the automatic recommendation requires speed and prediction agreement.
